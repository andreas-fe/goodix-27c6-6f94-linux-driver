# Goodix GF3268 — Reproducible Build and Installation

**Current source includes native new-finger enrollment, targeted deletion, standby open recovery and enrollment after deleting every template.** Normal use is KDE/fprintd; no Python capture or separate host bind is required.

## 1. What Was Reproduced

The hardware-tested installation originated from the project's locally modified libfprint 1.94.5 tree. For independent reproduction, the **public redacted source** was additionally integrated into a fresh official **libfprint v1.94.10** tree, built successfully and passed all 23 native driver API simulations plus libfprint's SSM/device suites. That clean upstream build was not substituted for the user's working hardware installation.

Use the pinned clean source recipe below to reproduce compilation and tests. Live hardware additionally needs privately configured transport constants and ABI compatibility with the target distribution. A passing offline build with zero key placeholders is not a working sensor installation.

Test target: GF3268 firmware `01010032`, USB `27c6:6f94`. Other versions require separate validation. Empty template storage is supported on the previously provisioned device; factory initialization remains untested.

## 2. Dependencies and Separate Working Directories

For Arch/CachyOS, the required tools/libraries can be installed with:

```bash
sudo pacman -S --needed base-devel git meson ninja pkgconf glib2 libgusb openssl libgudev cairo gobject-introspection python python-cryptography
```

Dependencies differ by distribution. OpenSSL 3 and a C/C++ toolchain are required. The optional local packaging helper additionally uses `bsdtar`, `makepkg`, `fakeroot` and `zstd` from the Arch packaging environment.

```bash
git clone https://github.com/andreas-fe/goodix-27c6-6f94-linux-driver.git
cd goodix-27c6-6f94-linux-driver
export GOODIX_REPO="$PWD"
mkdir -p "$HOME/.local/src/goodix-private"
chmod 700 "$HOME/.local/src/goodix-private"
export GOODIX_SOURCE="$HOME/.local/src/goodix-private/libfprint-v1.94.10"
export GOODIX_BUILD="$HOME/.local/src/goodix-private/build"
git clone --branch v1.94.10 --depth 1 https://gitlab.freedesktop.org/libfprint/libfprint.git "$GOODIX_SOURCE"
```

The official archive used for the independently checked build was:

```text
https://gitlab.freedesktop.org/api/v4/projects/libfprint%2Flibfprint/repository/archive.tar.gz?sha=v1.94.10
archive source root: libfprint-v1.94.10-0c97a47d8ef405cd577b87058c1e89cae9d242e7
```

Keep the private build tree outside the public Git checkout once it contains working constants. Do not upload compiled libraries/packages from that tree.

## 3. Integrate the Public Driver

```bash
python3 scripts/integrate_driver.py --source "$GOODIX_SOURCE"
```

This helper is deliberately pinned to upstream 1.94.10. It copies the four driver C/H files and updates the top-level driver list/helper mapping and libfprint source mappings. It uses upstream's OpenSSL helper dependency. It refuses a different version or a tree already containing this driver, so a second invocation cannot silently overwrite privately configured source. Use a fresh tree to repeat integration.

Manual equivalents are the `default_drivers`, `driver_helper_mapping`, `driver_sources` and `helper_sources` entries. The helper makes the tested edits reproducible rather than depending on the local development tree.

## 4. Configure Private Transport Keys Before Live Use

Public `driver/goodixsdcp_crypto.c` intentionally contains zero AES/HMAC constants. These are static vendor transport constants, distinct from the fresh P-256 SDCP session key generated by the driver for enrollment.

A compatible vendor adapter and the offline emulator are described in [Windows Driver Adapter DLLs](../windows_binaries/README.md) and the [key-setup section](NATIVE_ENROLLMENT.md#public-transport-key-setup-required-for-sdcp). With the corresponding optional emulator dependencies installed:

```bash
export GOODIX_SENSOR_ADAPTER_DLL="/absolute/path/to/compatible/GoodixMocSensorAdapter.dll"
python3 protocol/emulate_ki.py
```

The emulator's offsets are vendor-build-specific. Its output contains private values; keep it local. A different DLL with the same filename is not automatically compatible. No vendor DLL or derived working constants are included here.

Set `GOODIX_AES_KEY` to the locally derived 16-byte AES key encoded as 32 hexadecimal characters and `GOODIX_MAC_KEY` to the 32-byte HMAC key encoded as 64 hex characters. To enter values without placing them in literal shell commands:

```bash
read -r -s -p "AES transport key (hex): " GOODIX_AES_KEY
echo
read -r -s -p "HMAC transport key (hex): " GOODIX_MAC_KEY
echo
export GOODIX_AES_KEY GOODIX_MAC_KEY
python3 scripts/configure_transport_keys.py --driver-dir "$GOODIX_SOURCE/libfprint/drivers/goodixsdcp"
unset GOODIX_AES_KEY GOODIX_MAC_KEY
```

The configurator validates both keys before any write, rejects zero/incorrect lengths, refuses replacing different existing keys, writes the separate crypto source with mode 0600 and prints no values. It refuses editing the public repository's own driver file. Exporting Python key variables alone does **not** configure C; the explicit configurator step does.

For offline compilation/tests only, this step can be omitted: synthetic-peer tests work with placeholders. Do not try to operate the encrypted sensor channel with those placeholders.

## 5. Build and Run Offline Checks

```bash
meson setup "$GOODIX_BUILD" "$GOODIX_SOURCE" --prefix=/usr --libdir=lib -Ddrivers=goodixsdcp -Ddoc=false -Dintrospection=false -Dgtk-examples=false
ninja -C "$GOODIX_BUILD"
python3 -m unittest discover -s tests -q
python3 scripts/test_native_driver.py --source "$GOODIX_SOURCE" --build "$GOODIX_BUILD"
meson test -C "$GOODIX_BUILD" fpi-ssm fpi-device --print-errorlogs
```

Observed public results: **55 Python tests,23 native API simulations and both libfprint suites pass**. Four of the Python checks protect private C key configuration. Driver API simulations use fake USB/initial handshake acceptance; actual C crypto is independently checked by eight synthetic-peer tests. They do not replace hardware verification.

The runner supports upstream's archives and the optional extra SigFM archive in the older local fork. Clean upstream 1.94.10 builds need no SigFM stub or private archive. No locally saved fingerprint records are used in these tests.

## 6. Choose Installation Appropriate to Your Distribution

First keep password login available and close competing fingerprint dialogs. This project replaces the libfprint library; it is not a kernel module and does not require rebuilding initramfs or flashing firmware.

**Arch/CachyOS:** Prefer a distribution-compatible local provider package as described in [Maintenance](MAINTENANCE.md). It records ownership correctly, so normal updates do not silently replace an untracked library modification. The actual tested package preserved the existing distribution companion files and replaced only the already tested library.

**Manual installation:** The optional `scripts/install_native_driver.py` is specific to systemd hosts with `/usr/lib/libfprint-2.so.2.0.0` and `/var/lib/fprint`. Inspect paths and target ABI first. The clean source build is not permission to downgrade a newer distribution's API. Compare its exported public symbols with the current library and check `ldd -r` output; these are basic checks, not a proof of every ABI detail.

```bash
sha256sum "$GOODIX_BUILD/libfprint/libfprint-2.so.2.0.0"
sudo python3 scripts/install_native_driver.py --candidate "$GOODIX_BUILD/libfprint/libfprint-2.so.2.0.0" --expected-sha256 THE_REVIEWED_LOCAL_CHECKSUM
```

The installer requires a checksum, verifies ELF/checksum before service changes, saves the old library and host references privately, replaces the library atomically and restarts fprintd. It restores the previous library if installation fails. It does not delete templates or change PAM configuration. A distribution update can replace a manually installed library; a custom package is preferable.

Manual library rollback:

```bash
sudo python3 scripts/install_native_driver.py --restore-backup /var/lib/goodixsdcp-backups/SELECTED_BACKUP
```

Host reference backups are not automatically restored. Restoring a library/reference file does not restore deleted on-chip fingerprints. If using a provider package, restore/reinstall via the package manager to keep ownership consistent.

## 7. Standard Desktop Validation

```bash
fprintd-list "$USER"
fprintd-enroll -f right-thumb
fprintd-verify -f right-thumb
```

Or use KDE System Settings → Users → Fingerprint. Choose a free slot for a deliberate new enrollment. Lift/reposition between accepted samples. The driver reports 13 stages; fprintd adds a precheck, making 14 on D-Bus. Existing prints do not need re-enrollment just to install the update.

After a successful enrollment, test standard verification, practical lock/unlock, standby/wake and reboot on your machine. For the destructive empty-store reproduction, read the [full evidence and recovery limits](EMPTY_STORE_ENROLLMENT.md) first. Do not repeatedly retry an uncertain commit or clear storage as an automatic repair.

The tests and hardware results are version/device-specific, not an unrestricted compatibility or complete attestation claim.
